# 迁移与更新故障覆盖

- HTTP-01 验证失败：迁移前检查 A/AAAA、端口占用和本机 ACME webroot；证书失败提示云端 VCN/NSG 与主机 INPUT 放行 TCP 80。安装不会清空防火墙或 SSH 规则。
- Nginx `worker_connections` 超出文件限制：服务单元和配置均设置 65536。
- 面板/订阅监听未就绪：从数据库读取端口，等待服务 active 和 TCP listener，并保留完整服务日志诊断路径。
- Xray 缺少本地入站：克隆库将 `node_id` 设为 SQL `NULL`，续跑修复旧版本的 `0` 并验证没有远端入站残留。
- AnyTLS 更新 `ETXTBSY` 或服务未启动：二进制先写新 inode 后原子替换；同步程序会修复 inactive 服务再验证 TLS listener。
- AnyTLS 部署：独立生成本机密钥和凭据，只提供符合当前本机账号条件的线路；自动模式只添加 TCP 24443 主机规则，云安全组还需单独放行。它不自动汇入中心面板原生订阅。
- 节点身份错误或重复：新管理密码、管理路径、REALITY 密钥、short ID、UUID、订阅 ID 和 node-sync token 每台重新生成；身份只写目标机 `/root/proxy-stack`，不从种子复制旧 JSON。
- Hosts 地址覆盖其他节点：注册器拒绝跨节点共享 Hosts 组，且为每个新入站设置新机地址。
- 订阅漏节点：注册器等待中心节点导入至少两个入站，验证 REALITY 目标不是本机，再附加明确指定的账号并触发订阅重新生成。
- 迁移续跑：状态绑定种子摘要、域名、IP、防火墙模式；每阶段保存，只有相同安装可 `--resume`，不会重复生成身份。
- 面板更新桥：面板以绝对路径运行 `systemd-run` 时在其私有服务命名空间绑定适配器；宿主机 systemd 不变。助手只接受稳定版请求并自行校验官方 SHA256。
- 面板更新回滚：恢复时保留 `/var/lib/proxy-stack` 授权挂载点，不删除后重建父目录；原始更新错误和回滚错误分别记录。`panel-update/recover.py` 可从明确给定的快照恢复缺失的 `bin/`。
- Xray 核心更新：事务备份当前核心，走 3x-ui 版本 API，检查节点流量与实际协议验证；失败时用同目录临时文件加原子替换还原。核心自动更新默认不启用定时器，避免未验证的新核心中断客户端。

## 兼容性边界

本机验证不能代替 Stash、Happ、dae 等真实客户端握手测试。通过更新脚本表示节点服务端检查通过，不代表每种客户端都兼容。不要把自动滚动到最新核心设为无人工验证的默认策略。
